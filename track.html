§ 00 / PRELUDE

What Meridian is, in one breath.

A private, evidence-based mental health platform that routes every user turn through deterministic safety guardrails before any LLM ever sees the text — backed by a stateful LangGraph DAG, local ONNX classifiers, Presidio PII redaction, and cross-session pgvector memory.

This document reconstructs the journey from the first static HTML commit (3ac7760) to the current adaptive-screening, prompt-cached, SPA topology at HEAD (7632b90). Each phase is recorded with four anchors — why the pivot was forced, what was actually built, when it landed, and where in the codebase it lives — so the trail is recoverable, not merely commemorative.

The production shape.

Compute-intensive ML and state orchestration are physically separated from edge-cached delivery. The client never touches the model; the model never serves a stylesheet.

§ 02 / THE GRAPH

Every turn passes through deterministic guardrails.

Standard chatbots pipe user input straight to an LLM. Meridian doesn't. ClinicalState flows through a LangGraph DAG where each node is small, testable, and can short-circuit the path before any generative model is invoked.

Fig. 03LangGraph DAG · ClinicalState transitions

The global state — ClinicalState

  • messages — append-only via LangGraph add_messages reducer
  • current_message — redacted text after Security node
  • embedding_buffer · char_buffer_total — accumulate turn-by-turn during screening
  • prob_history — Phase-10 rolling probability trail
  • crisis_detected · diagnosis_ready — short-circuit flags

May 20, 2026 · commits 4dea501 → 3d6a47f

The monolith falls apart.

Why
The backend was serving its own static HTML through FastAPI StaticFiles. Style tweaks reloaded PyTorch and ONNX pools; ML hardware burned cycles serving JS bundles; the wildcard mount kept stealing /health liveness probes.
What
Decouple. The frontend became a Vercel-edge SPA. The backend became a headless FastAPI API on Hugging Face Spaces. CORS moved from ["*"] to a strict whitelist read from ALLOWED_ORIGINS.
When
May 20, 2026 — the first significant pivot, less than a day in.
Where
backend/main.py · Dockerfile · environment variable boundary

The original mount looked like this — innocent until it scaled:

# before — coupling at the file system
app.mount("/", StaticFiles(directory="frontend", html=True), name="static")

It was replaced with explicit, traceable origin governance:

# after — strict whitelist, no wildcard
_ALLOWED_ORIGINS = [
    o.strip() for o in os.getenv(
        "ALLOWED_ORIGINS",
        "https://meridian-frontend-green.vercel.app,http://localhost:3000",
    ).split(",") if o.strip()
]
app.add_middleware(
    CORSMiddleware,
    allow_origins=_ALLOWED_ORIGINS,
    allow_credentials=True,
)
Outcome

Docker build times dropped ~40% once frontend assets stopped being copied into the ML container. Liveness probes stopped getting intercepted by the SPA fallback route.

The UUID → TEXT migration

The first schema typed sessions.id as UUID. The frontend, meanwhile, was minting flexible client-side hashes — and every insert failed validation. Rather than rewrite the client, every dependent FK was migrated to TEXT.

CREATE TABLE IF NOT EXISTS public.sessions (
  id                TEXT PRIMARY KEY,  -- was UUID; flexible client hashes
  user_id           UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  mode              TEXT NOT NULL CHECK (mode IN ('diagnosis','therapy')),
  embedding_buffer  JSONB NOT NULL DEFAULT '[]',
  char_buffer_total INT   NOT NULL DEFAULT 0,
  prob_history      JSONB NOT NULL DEFAULT '[]', -- added Phase 10
  diagnosis_ready   BOOLEAN NOT NULL DEFAULT false,
  crisis_detected   BOOLEAN NOT NULL DEFAULT false,
  risk_scores       JSONB NOT NULL DEFAULT '{}'
);

Row-level security as the default

Policies were written defensively — DROP POLICY IF EXISTS followed by CREATE POLICY — so reruns never explode:

ALTER TABLE public.messages ENABLE ROW LEVEL SECURITY;
CREATE POLICY "messages: own sessions" ON public.messages
  FOR ALL USING (
    session_id IN (
      SELECT id FROM public.sessions WHERE user_id = auth.uid()
    )
  );
Lost risk_scores

A side-effect bug: between turns the backend was dropping the running risk dictionary. The fix was a single line — hydrate from Supabase on the way in: "risk_scores": sess.get("risk_scores") or {}.

Onboarding stopped silently dropping data.

Why
Users completed onboarding — display name, modality, age — pressed consent, and then watched their profile page show empty fields. /profile/consent was ignoring the request body and only setting consent_given=true.
What
A typed Pydantic ConsentPayload with field-level validation, plus a single upsert keyed on on_conflict="id" that writes consent and metadata in one transaction.
When
May 23, 2026.
Where
backend/main.py::accept_consent · src/pages/Onboarding.jsx
class ConsentPayload(BaseModel):
    display_name:       Optional[str]   = Field(None, max_length=80)
    preferred_modality: Optional[Literal["cbt","act","dbt","mindfulness","sfbt"]] = "cbt"
    consent_given:      bool = False

@app.post("/profile/consent")
def accept_consent(body: ConsentPayload, user=Depends(get_current_user), sb: Client=Depends(get_supabase)):
    if not body.consent_given:
        raise HTTPException(status_code=400, detail="consent_given must be true")
    upsert = {"id": user.id, "consent_given": True, "consent_at": now}
    if body.display_name:       upsert["display_name"] = body.display_name
    if body.preferred_modality: upsert["preferred_modality"] = body.preferred_modality
    sb.table("profiles").upsert(upsert, on_conflict="id").execute()

May 24, 2026 · commit c51f551

The keyword filter missed "yes".

Why
Standard keyword-based safety filters scan for "suicide", "self-harm". They fail catastrophically when a patient answers PHQ-9 Q9 — "thoughts that you would be better off dead" — with a single character: "1", or "yes".
What
A contextual interceptor that reads the previous assistant turn for the Q9 marker, then parses the user's reply for affirmatives and PHQ-9 score values 1–3.
When
May 24, 2026.
Where
backend/main.py::_is_phq9_q9_crisis
_PHQ9_Q9_MARKER = "thoughts that you would be better off dead"
_AFFIRMATIVE_RE = re.compile(
    r"\b(yes|yeah|yep|sometimes|often|always|daily|every day|"
    r"more than half|nearly every day|[1-3])\b",
    re.IGNORECASE,
)

def _is_phq9_q9_crisis(messages, current_user_text):
    last_assistant = next((m.content for m in reversed(messages) if m.role == "assistant"), None)
    if not last_assistant or _PHQ9_Q9_MARKER not in last_assistant.lower():
        return False
    text = current_user_text.strip().lower()
    if re.search(r"\b(0|none|never|not at all|no)\b", text) and not _AFFIRMATIVE_RE.search(text):
        return False
    return bool(_AFFIRMATIVE_RE.search(text))
Routing on positive

If the interceptor returns true, crisis_detected is flipped before the LangGraph executes — the Supervisor Router sends the turn directly to the Crisis Node, which renders region-aware emergency helplines instead of running the LLM.

export function AuthProvider({ children }) {
  const [session, setSession] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    supabase.auth.getSession().then(({ data: { session: s } }) => {
      setSession(s); setLoading(false);
    });
    const { data: { subscription } } = supabase.auth.onAuthStateChange((_e, s) => {
      setSession(s); setLoading(false);
    });
    return () => subscription.unsubscribe();
  }, []);

  return <AuthContext.Provider value={{ session, loading }}>{!loading && children}</AuthContext.Provider>;
}

May 24, 2026 · commits 08068f1, 367739c

From eight-second waits to live tokens.

Why
Blocking POST chat round-trips spent 5–8 seconds waiting for the LLM to finish before the user saw a single character. That latency reads as broken to anyone, but reads as alarming to a user in distress.
What
A FastAPI StreamingResponse SSE endpoint with anti-buffering headers, paired with a client-side ReadableStreamDefaultReader that parses a six-event state machine: stream_start · token · replace · message · crisis · done.
When
May 24, 2026.
Where
backend/main.py::chat_stream · src/pages/Chat.jsx

Defeating reverse-proxy buffering

return StreamingResponse(
    event_stream(),
    media_type="text/event-stream",
    headers={
        "Cache-Control":     "no-cache, no-transform",
        "X-Accel-Buffering": "no",    # Nginx / Cloudflare bypass
        "Connection":        "keep-alive",

The six events the client handles

Event Client action Used for
stream_start Dismiss typing loader, init bubble Start of stream
token Append to accumulating string Per-character delivery
replace Overwrite buffer with sanitized text Safety guardrail mid-stream
message Replace with structured payload Reports, PHQ-9 cards
crisis Unmount bubble, mount CrisisBlock Implicit Q9 trigger
done Remove cursor, parse markdown Stream complete
Idempotent finalize

An inner _finalize() closure is called both on graceful done and inside except. A boolean guard makes it idempotent — disconnects mid-stream still persist the partial assistant reply and session state.

May 24, 2026 · commit c1e0ddc

Memory survived the restart.

Why
ChromaDB lived in-process and in-memory. Every container restart wiped it. Worse, retrieval was locked to the current session_id — if a user opened a new conversation, Meridian forgot they'd ever mentioned their parents.
What
Migration to pgvector on Supabase. 384-dimensional L2-normalized embeddings from all-MiniLM-L6-v2, indexed with ivfflat on cosine ops, retrieved via a stored RPC scoped by user_id — not session.
When
May 24, 2026.
Where
backend/agents/memory.py · scripts/supabase_schema.sql
CREATE INDEX IF NOT EXISTS memory_embeddings_vector_idx
  ON public.memory_embeddings
  USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 50);

CREATE OR REPLACE FUNCTION public.match_memory_embeddings(
  query_embedding vector(384),
  target_user_id  uuid,
  match_count     int DEFAULT 2
) RETURNS TABLE (id bigint, session_id text, content text, similarity float)
AS $$
BEGIN
  RETURN QUERY
  SELECT m.id, m.session_id, m.content,
         1 - (m.embedding <=> query_embedding) AS similarity
  FROM  public.memory_embeddings m
  WHERE m.user_id = target_user_id AND m.embedding IS NOT NULL
  ORDER BY m.embedding <=> query_embedding LIMIT match_count;
END; $$ LANGUAGE plpgsql STABLE;

Lazy singleton — pay the load cost once

# 80 MB model, 3 s warm-up; load on first call, never again
@lru_cache(maxsize=1)
def _get_embedder() -> SentenceTransformer:
    logger.info(f"Loading embedding model: {EMBED_MODEL_NAME}")
    return SentenceTransformer(EMBED_MODEL_NAME)

def _embed(text: str) -> List[float]:
    # L2 normalise so cosine == dot product downstream
    return _get_embedder().encode(text, normalize_embeddings=True).tolist()

09
May 24, 2026 · therapy node hardening

Cache the prefix, vary the suffix.

Why
OpenAI's prompt-caching auto-discounts identical prefixes ≥ 1024 tokens by 50%. The original therapy prompt builder spliced dynamic RAG context before the static modality prompt, which mutated the prefix on every turn — breaking the cache every time.
What
Reordered the message list so the static modality prompt sits at index 0 (perfectly cacheable), and dynamic RAG context is isolated as its own system message at index 1.
When
May 24, 2026.
Where
backend/agents/therapy.py::_build_request
def _build_request(state: ClinicalState):
    modality = state.get("modality") or "cbt"

    # 1. static modality prompt — cacheable across all users and turns
    llm_messages = [{"role": "system", "content": get_prompt(modality)}]

    # 2. dynamic RAG — isolated at index 1, doesn't poison the prefix
    past = retrieve_similar(state["session_id"], state["current_message"], n_results=2)
    if past:
        llm_messages.append({
            "role": "system",
            "content": "[Relevant context from this user's previous sessions]:\n\n"
                       + "\n\n---\n\n".join(past),
        })
Measured impact

~50% reduction in both input-token cost and time-to-first-token on cache-hit turns. The therapy node became materially cheaper at scale without any change to model behavior.

May 25, 2026 · commit 7632b90 · HEAD

The screening gate listens for confidence.

Why
The diagnosis gate was a static threshold: chars ≥ 1000 AND turns ≥ 3. Users showing severe distress in their first sentence were forced to keep typing. Ambiguous users got rushed to a verdict the moment the static limit tripped.
What
An SPRT-style adaptive decision policy. The ONNX classifier runs every turn; four rules can fire to close the screening. Below them, a confidence-aware _adaptive_target shrinks the displayed progress bar as the signal clarifies — the bar visually accelerates when the model becomes certain.
When
May 25, 2026 — current HEAD.
Where
backend/agents/diagnosis.py · backend/main.py::_persist_session

The four rules — in order of evaluation

  1. Early-High Fire — p ≥ 0.80Strong depression signal; close immediately. Honour user urgency.
  2. Early-Low Fire — p ≤ 0.20 ∧ turns ≥ 3 ∧ chars ≥ 400Absence of signal needs more evidence than presence. Stricter floors.
  3. Convergence — spread ≤ 0.08 over 3 turns, outside 0.4–0.6 dead-zoneStable signal away from the middle counts as decided.
  4. Ceiling — turns ≥ 8 ∨ chars ≥ 1500Patience exhausted; emit ceiling_high or ceiling_low by latest p.
Fig. 06SPRT-style decision policy · evaluated every turn

The adaptive target — confidence drives the progress bar

def _adaptive_target(latest_prob: float, current_chars: int) -> int:
    confidence = abs(latest_prob - 0.5) * 2   # 0 = ambiguous, 1 = certain
    if confidence >= 0.70:   candidate = max(current_chars, 250)   # shrink toward done
    elif confidence >= 0.50: candidate = max(current_chars, 700)
    elif confidence >= 0.30: candidate = 1000
    else:                    candidate = 1500                      # expand ceiling
    return max(candidate, current_chars + 1)

The persistence reset seam

LangGraph reducers accumulate by design — they don't reset. To start a clean screening cycle after a fire, the reset happens at the persistence boundary, by intercepting the diagnosis_ready false → true edge and overwriting the buffers before they hit Supabase:

just_fired = bool(result.get("diagnosis_ready", False)) and not bool((prev_sess or {}).get("diagnosis_ready", False))
if just_fired:
    embedding_buffer  = []
    char_buffer_total = 0
    prob_history      = []
    # next turn starts a brand-new, clean cycle
Empathetic copy

Clinical jargon in the UI was rewritten in the same pass: "Linguistic Mapping Integrity" became Signal confidence; "raw metrics" became chars analyzed. The visible string in the progress bubble is now Signal confidence · 247/250 chars analyzed.

§ 04 / DIAGNOSES

Four bugs worth remembering.

Not every fix earns a place in the chronicle. These four did — because each one revealed a category of mistake that's easy to repeat.

i

The silent onboarding discard

Symptom Users completed onboarding, gave a name, picked a modality — and the Profile page showed nothing.

Cause /profile/consent ignored the request body and parsed an empty dict.

Fix Strongly-typed ConsentPayload; one upsert with on_conflict="id"; metadata and consent flag move together.

ii

The stale-token 401 loop

Symptom Tabs left open past the Supabase token expiry crashed on the next message; manual reload required.

Cause The old static-HTML grabbed the JWT once at login and reused it forever.

Fix getAuthHeaders() calls supabase.auth.getSession() per request and lets the SDK refresh; if the session is dead, the user is signed out cleanly instead of deadlocking.

iii

The invisible message loss

Symptom Occasional missing chat turns at peak DB load. No errors in production logs.

Cause _store_messages swallowed all exceptions with a bare warning, hiding the traceback.

Fix exc_info=True on every persistence error, with the session ID embedded in the log line so failures become traceable.

iv

The cold-start thrashing

Symptom Every /chat call paid an extra 3–5 seconds.

Cause The 80 MB SentenceTransformer and Supabase client were instantiated per request.

Fix @lru_cache(maxsize=1) on the loaders. Heavy boot once at first call, then milliseconds per turn after.

Three properties that hold across all ten phases

  • Zero-leakage privacy. Names, emails, payment data are stripped locally by Presidio before any cloud endpoint sees the turn.
  • Adaptive speed. Severe symptoms get intervention in as few as 2 turns / 200 characters. Ambiguous cases get up to 8 turns of careful collection.
  • Cross-session continuity. pgvector retrieval lets last week's disclosure inform this week's response without manual recall.
